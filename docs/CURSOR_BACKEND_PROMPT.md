## 1. Stack (pin these — do not upgrade majors)

- Node 20+ / TypeScript 5 (strict), ESM (`"type": "module"`)
- **Express 5** (`express@^5`) — async handler errors propagate natively, no `express-async-errors`
- **Prisma 6** (`prisma@^6.19`, `@prisma/client@^6.19`) with **SQLite** (`file:./dev.db`). Do NOT use Prisma 7/8 — their config/adapter changes are out of scope.
- **zod@^4** for all request validation (body, params, query)
- `jsonwebtoken` (HS256) + `bcryptjs` for auth
- `cors`, `helmet`, `morgan` (dev logging)
- Dev: `tsx` (watch + run), `vitest` + `supertest` for tests

SQLite note: Prisma's SQLite connector has no native enums and no `mode: "insensitive"`. Store enums as `String` and validate with zod. For case-insensitive search, SQLite `LIKE`/`contains` is already case-insensitive for ASCII — use `contains` without `mode`.

## 4. Prisma schema (implement this; adjust only syntax)

```prisma
generator client { provider = "prisma-client-js" }
datasource db { provider = "sqlite"  url = env("DATABASE_URL") }

model User {
  id           Int        @id @default(autoincrement())
  name         String
  email        String     @unique          // store lowercased
  passwordHash String
  role         String     @default("AGENT") // ADMIN | AGENT
  createdAt    DateTime   @default(now())
  assignedTickets Ticket[] @relation("TicketAssignee")
  createdTickets  Ticket[] @relation("TicketCreator")
  messages     Message[]
  activities   Activity[]
}

model Ticket {
  id              Int       @id @default(autoincrement())
  subject         String
  customerName    String?
  customerEmail   String?
  description     String
  status          String    @default("OPEN")    // TicketStatus
  priority        String    @default("MEDIUM")  // TicketPriority
  priorityRank    Int       @default(2)         // denormalised for ORDER BY; ALWAYS set together with priority
  assigneeId      Int?
  assignee        User?     @relation("TicketAssignee", fields: [assigneeId], references: [id], onDelete: SetNull)
  createdById     Int?
  createdBy       User?     @relation("TicketCreator", fields: [createdById], references: [id], onDelete: SetNull)
  createdAt       DateTime  @default(now())
  updatedAt       DateTime  @default(now())     // set MANUALLY in services (not @updatedAt) so no-op PATCH doesn't bump it
  resolvedAt      DateTime?
  firstResponseAt DateTime?
  messages        Message[]
  activities      Activity[]

  @@index([status])
  @@index([priorityRank])
  @@index([assigneeId])
  @@index([updatedAt])
  @@index([createdAt])
}

model Message {
  id        Int      @id @default(autoincrement())
  ticketId  Int
  ticket    Ticket   @relation(fields: [ticketId], references: [id], onDelete: Cascade)
  type      String   // REPLY | NOTE
  body      String
  authorId  Int?
  author    User?    @relation(fields: [authorId], references: [id], onDelete: SetNull)
  createdAt DateTime @default(now())
  @@index([ticketId, createdAt])
}

model Activity {
  id        Int      @id @default(autoincrement())
  ticketId  Int
  ticket    Ticket   @relation(fields: [ticketId], references: [id], onDelete: Cascade)
  type      String   // ActivityType
  actorId   Int?
  actor     User?    @relation(fields: [actorId], references: [id], onDelete: SetNull)
  fromValue String?
  toValue   String?
  createdAt DateTime @default(now())
  @@index([ticketId, createdAt])
}

model Setting {
  key   String @id   // "slaHours"
  value String
}
```
`onDelete: Cascade` on Message/Activity is the data-integrity policy: deleting a ticket removes its thread and history — no orphans.

## 5. Business rules (must all hold)

1. **Required fields** — subject (3–200, trimmed), description (1–5000, trimmed), and at least one of customerName/customerEmail. Empty strings → `null`. Validation errors return `details` keyed by field; the "need a customer" error key is `customer`.
2. **Overdue** — `status !== 'RESOLVED' && createdAt < now - 24h`. Computed at read time (never stored). `?overdue=true` filter uses the same rule in the `where` clause (`status: { not: 'RESOLVED' }, createdAt: { lt: cutoff }`).
3. **Resolution** — RESOLVED tickets are excluded from open/in-progress/overdue/urgent/unassigned/slaBreached counts and flags. Moving to RESOLVED sets `resolvedAt = now`; moving away clears it.
4. **History** — create activity rows for status, priority, assignee changes, detail edits, ticket creation, replies and notes, inside the **same `prisma.$transaction`** as the change. Assignee activity stores **names** (snapshot) in from/to; `null` means Unassigned. Only record fields whose value actually changed.
5. **updatedAt** — set to `now` on any real ticket change and on every new message. A PATCH that changes nothing returns 200 without writing.
6. **SLA** — `slaHours` from `Setting` (default 4, seed it). `slaDueAt = createdAt + slaHours`; `slaBreached = status !== RESOLVED && firstResponseAt === null && now > slaDueAt`. `firstResponseAt` is set by the first `REPLY` only. `?slaBreached=true` filter uses the same rule in `where` (`status: { not: 'RESOLVED' }, firstResponseAt: null, createdAt: { lt: now - slaHours }`).
7. **Priority sort** — `orderBy: [{ priorityRank: order }, { updatedAt: 'desc' }]`. Keep `priorityRank` in sync with `priority` on every create/update (use `PRIORITY_RANK` map).
8. **Authorization** — all routes except `/api/health` and `/api/auth/login` require a valid Bearer JWT. `DELETE /tickets/:id` and `PATCH /settings` require ADMIN (403 `FORBIDDEN` otherwise). Message author and activity actor always come from `req.user`, never the request body.
9. **assigneeId** must reference an existing user → else 400 `VALIDATION_ERROR` with `details.assigneeId = "Assignee not found"`.
10. **Ids** — non-integer `:id` → 400 `VALIDATION_ERROR`; integer but missing → 404 `NOT_FOUND` with message like `"Ticket 99 not found"`. Message/activity endpoints on a missing ticket also 404.
11. **Strict bodies** — zod `.strict()` on create/patch/message/settings bodies; unknown keys → 400. PATCH with `{}` → 400 ("Provide at least one field to update").

## 6. Implementation notes

- **Serializer** (`tickets.serializer.ts`): `serializeTicket(row, { slaHours, now })` adds `isOverdue`, `slaDueAt`, `slaBreached`, `messageCount` (via `_count: { messages: true }` in the query — no N+1), and maps `assignee`/`createdBy` to `UserSummary` (`id,name,email,role` — **never** `passwordHash`). Dates → `.toISOString()`.
- **List query**: build one `where` object from the parsed query (AND across params, `in` for CSV lists, `OR` for `q`), run `count` and `findMany` in a single `$transaction([...])`, return the `{ data, meta }` envelope. Use `skip/take`. Include `assignee`, `createdBy`, `_count`.
- **Query parsing**: CSV params → `z.string().transform(s => s.split(',').filter(Boolean)).pipe(z.array(z.enum(STATUSES)))`. `page`/`pageSize` via `z.coerce.number().int()` with bounds and defaults. `assigneeId` accepts positive int, `"unassigned"` (→ `assigneeId: null`), or `"me"` (→ `req.user.id`).
- **Dashboard**: run all counts in parallel with one `$transaction([...count()])`; no loading all rows into memory.
- **Error handler**: last middleware. AppError → its status/code/message/details; ZodError → 400 with `details` built from `issue.path.join('.') → issue.message` (first message per field; map the customer refinement to key `customer`); `SyntaxError` from `express.json()` → 400 `BAD_REQUEST`; Prisma `P2025` → 404; anything else → log with `console.error` and return 500 `INTERNAL_ERROR` / `"Something went wrong"`. Never send stack traces.
- **Auth**: `POST /auth/login` lowercases email, `bcrypt.compare`, returns `{ token, user }`; same 401 `INVALID_CREDENTIALS` message ("Invalid email or password") for unknown email and wrong password. JWT payload `{ sub: userId, role }`. `requireAuth` re-loads the user from DB (so deleted users are rejected) and sets `req.user`.
- **CORS**: `cors({ origin: env.CORS_ORIGIN })`. Body limit `express.json({ limit: '100kb' })`. Mount all routers under `/api`.
- `/api/health` returns `{ status: "ok" }` after a trivial `prisma.$queryRaw\`SELECT 1\`` (return 503 `{ status: "error" }` if the DB is unreachable).
